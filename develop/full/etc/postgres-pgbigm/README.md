## 2. 第一批：由 Navicat 传输序列和表结构，不传数据

优先使用 **工具 → 结构同步**，源为 A/erp2027/public，目标为本地/erp2027/public。
结构同步支持查看部署脚本，并在“编辑脚本”中调整语句顺序；这比依赖“数据传输”的自动排序更可控。

比较选项：

- 选择表、序列、主键、唯一键、索引、检查，以及需要的表选项。
- 暂不比较/部署外键、触发器、函数、视图等本批不涉及的对象。
- 关闭比较所有者、级联删除；源库部分表属于 erp2027 角色，本地统一使用 postgres。

在比较结果树中只选择本批业务表和普通序列。本次实时 A 库有 120 张表、24 个序列，其中：

- 21 个普通序列应在引用它们的表之前创建。
- ck_warehouse_locations.id、ck_warehouses.id、user_notices.id 是 GENERATED BY DEFAULT AS IDENTITY。
  不要额外部署这 3 个 identity 序列，让 identity 建表语句自行创建它们。
- 本次结构同步自动正确处理了序列/建表顺序及 identity 序列排除，第一批无需手工重排。
- gtrgm 属于 pg_trgm；不要把它当成业务类型进行 DROP/CREATE。
- 不传扩展自带的函数、运算符、操作符类。pg_bigm、pg_trgm 已经创建它们。

在**部署脚本**预览中确认顺序；必要时点击“编辑脚本”重排：

1. CREATE SEQUENCE（普通序列）。
2. CREATE TABLE（含列默认值及 identity 定义）。
3. 普通序列的 ALTER SEQUENCE ... OWNED BY（须在所属表已创建后）。
4. 主键、唯一键、索引和检查约束。

若生成的 SQL 把序列的 OWNED BY 放到建表前，也必须后移；只有序列本身先创建还不够。
identity 序列不要用普通 ALTER SEQUENCE ... OWNED BY 改归属。
不要执行删除扩展对象、删除业务表、修改已有列、复制源库所有者的操作。
首次目标是空库，只应部署本批新增对象。关闭“遇到错误时继续”，执行成功后再进入下一批。
本批部署脚本不应包含 FOREIGN KEY 或 CREATE TRIGGER，确认它们确实已经排除。

本次实时库的 pg_bigm 索引共 40 个；已启用扩展后在这一批正常建立。旧备份为 38 个。

## 3. 第二批：由 Navicat 传输业务函数

使用 **工具 → 数据传输**，源和目标仍为 A → 本地，关闭“包含所有者”和“遇到错误时继续”。
只勾选这 5 个 public 业务函数：

- check_deliverable_file_target()
- check_file_counter_increase()
- check_file_ref_target()
- qc_guard_inspection_plan_checks()
- qc_guard_inspection_plan_version()

不要全选函数。pg_trgm 和 pg_bigm 的 C 函数都由扩展管理，应排除。
尤其不能传 gtrgm_in、gtrgm_out、gin_*、similarity、show_trgm、show_bigm 等扩展内部函数。
即使 A 库某些扩展函数是手工创建、没有扩展成员归属，只要仍是引用 pg_bigm/pg_trgm
动态库的 C 函数，也不作为业务函数传输。

此时所有业务表应已存在。check_file_ref_target 使用 public.files%ROWTYPE，
因此函数不能放在建表前传输。若实时 A 库新增了业务函数，以本文“迁移前检查源库”的查询结果补齐。

## 4. 第三批：由 Navicat 直接传全部表的数据

工具 → 数据传输，源 A/erp2027/public，目标本地/erp2027/public。

| 项目 | 设置 |
| --- | --- |
| 对象 | 只选择全部业务表 |
| 插入记录 | 勾选 |
| 使用完整插入语句 | 勾选，保留原列名和 ID |
| 创建表 | 不勾选 |
| 创建前删除目标对象 | 不勾选 |
| 用级联删除 | 不勾选 |
| 遇到错误时继续 | 不勾选 |
| 序列、类型、函数、扩展等 | 不选择 |

若失败，先处理错误并明确清理本地已装载的数据，或另建一个空目标库重新执行。

## 5. 第四批：由 Navicat 补齐外键和业务触发器

再次使用 **工具 → 结构同步**，方向仍为 A → 本地。
启用表、外键和触发器的比较，在结果树中展开表，**只选择缺少的外键和触发器**。
不要部署其他不相关差异；特别是不要选表的删除/重建、字段变更、扩展对象、函数和序列变更。

执行前预览部署脚本，这一批应主要是：

```sql
ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY ...;
CREATE TRIGGER ...;
```

对应业务函数在第二批已经传入，触发器的依赖现在齐全。本次实时库为 38 个外键、5 个业务触发器。
本次比较还列出了检查约束及一个索引的重建差异，均未在收尾批次执行。
可在“部署选项”下拉菜单 → “编辑脚本”中取消不相关语句；本次最终预览只有 38 条 ADD FOREIGN KEY 和 5 条 CREATE TRIGGER，没有 DROP、CHECK 或字段变更。
关闭“遇到错误时继续”。新增外键要正常验证已有数据，不使用 NOT VALID 跳过验证。
如果 Navicat 输出 NOT VALID，必须随后通过 Navicat 执行对应 VALIDATE CONSTRAINT，确认全部通过。

这里使用 Navicat 的结构同步来补对象，不要重新勾选“创建表”再传一次，否则可能删除已经传入的数据。

## 6. 序列和结果验收（仍在 Navicat 中完成）

数据装载完毕后，在**本地目标库**的 Navicat 查询窗口执行本文“传输后校准本地序列”中的 SQL。
它仅校准序列状态，不替代业务表/函数/数据的 Navicat 传输。
该脚本兼顾 identity 和多个列共享同一个 nextval 序列，避免后续新增数据使用已存在的 ID。
例如 material_category.id 和 department_list.id 共享 department_list_id_seq，必须考虑两表最大 ID。

此校准不保证复制了 A 库实时 last_value（源库可能取过号但没落表）。
若需要精确保留停写时的序列状态，应在 A 库通过 Navicat 查询该状态，再在本地按相同状态设置。

在 Navicat 中分别对 A/B 执行本文“核对每张表行数”中的 SQL。
本地执行本文“检查序列下一值”中的 SQL，24 行的 safe 都应为 true。它是只读查询，不会消费序列值。
再核对关键数据，并在本地执行：

```sql
SELECT extname, extversion FROM pg_extension ORDER BY extname;
SELECT count(*) AS public_tables FROM pg_tables WHERE schemaname = 'public';
SELECT count(*) AS business_triggers FROM pg_trigger WHERE NOT tgisinternal;
SELECT count(*) AS foreign_keys,
       count(*) FILTER (WHERE NOT convalidated) AS unvalidated
FROM pg_constraint WHERE contype = 'f' AND connamespace = 'public'::regnamespace;
SELECT pg_get_serial_sequence('public.user_notices', 'id');
```

本次实时库验收值：120 张表、5,698 行、40 个 bigm 索引、5 个业务触发器、38 个已验证外键。
旧备份参考值为 119 张表、2,581 行、38 个 bigm 索引；实时库多了 material_standard_names_copy1 等数据变化。
A 库持续更新时行数可能不同，应以停写后的实时 A 库为准。
确认传输和验收完成后，再让本地业务程序连接并写入。

## 环境差异与验收边界

A 库实际为 PostgreSQL 18.6，本地运行 PostgreSQL 18.3；两边均启用 pg_bigm 1.2、pg_trgm 1.6。
本次逻辑迁移在这个组合上通过。操作系统从 Windows 换到 macOS 并不会自动补齐镜像中的扩展，
也不会自动修复 Navicat 对对象依赖的传输顺序；解决办法是安装扩展并按上面四批执行。

本次 3 个 identity 列：ck_warehouse_locations.id、ck_warehouses.id、user_notices.id。
material_category.id 与 department_list.id 共用 department_list_id_seq：校准后 last_value=48，
下一值=49，同时超过两表最大 ID（48 和 15）。全部 24 个序列的下一值检查通过。
校准保证超过已存 ID，不承诺与 A 库未使用号码的 last_value 完全相同。

本次没有对 A 库执行写入或结构变更。未做业务应用的全流程验收；正式要求全库一致时，
应在 A 库停写窗口内重做传输和验收。不要在这个已有数据的本地库上再次直接追加全量数据。

## 迁移辅助 SQL

以下 SQL 仅供在 Navicat 中手动执行，Docker 构建和容器启动均不会执行它们。

### 迁移前检查源库

```sql
-- 在 Navicat 的 A 库查询窗口执行；只读。
SELECT version();
SELECT extname, extversion, extnamespace::regnamespace AS schema_name
FROM pg_extension
ORDER BY extname;

-- 这些是扩展管理的函数，不能作为普通函数传输到本地。
SELECT e.extname, n.nspname, p.proname,
       pg_get_function_identity_arguments(p.oid) AS arguments
FROM pg_depend d
JOIN pg_extension e ON d.refclassid = 'pg_extension'::regclass AND d.refobjid = e.oid
JOIN pg_proc p ON d.classid = 'pg_proc'::regclass AND d.objid = p.oid
JOIN pg_namespace n ON n.oid = p.pronamespace
WHERE d.deptype = 'e' AND e.extname IN ('pg_bigm', 'pg_trgm')
ORDER BY e.extname, p.proname;

-- 候选业务函数（排除扩展成员；手工安装的扩展函数需根据语言/库再识别）。
SELECT n.nspname, p.proname,
       pg_get_function_identity_arguments(p.oid) AS arguments,
       l.lanname AS language, p.probin AS library
FROM pg_proc p
JOIN pg_namespace n ON n.oid = p.pronamespace
JOIN pg_language l ON l.oid = p.prolang
WHERE n.nspname = 'public'
  AND NOT EXISTS (
      SELECT 1 FROM pg_depend d
      WHERE d.classid = 'pg_proc'::regclass AND d.objid = p.oid
        AND d.refclassid = 'pg_extension'::regclass AND d.deptype = 'e'
  )
ORDER BY p.proname;

-- identity 列会自行建序列，不要再把它的序列作为普通序列提前传输。
SELECT table_schema, table_name, column_name, identity_generation
FROM information_schema.columns
WHERE table_schema = 'public' AND is_identity = 'YES';
```

### 传输后校准本地序列

```sql
-- 数据传输完成、目标库没有并发写入时，在本地目标库执行。
-- 同时处理 identity、serial，以及多个列共用的 nextval 序列。
-- 目标是避免后续 INSERT 使用已有 ID；不代表复制了 A 库的实时序列状态。
DO $sync$
DECLARE
    seq record;
    col record;
    column_max bigint;
    used_max bigint;
    current_value bigint;
BEGIN
    FOR seq IN
        SELECT c.oid, n.nspname, c.relname, q.seqstart, q.seqincrement
        FROM pg_class c
        JOIN pg_namespace n ON n.oid = c.relnamespace
        JOIN pg_sequence q ON q.seqrelid = c.oid
        WHERE n.nspname = 'public'
    LOOP
        IF seq.seqincrement <= 0 THEN
            RAISE EXCEPTION '需要单独处理递减序列 %.%', seq.nspname, seq.relname;
        END IF;
        used_max := NULL;
        FOR col IN
            WITH refs AS (
                SELECT ad.adrelid AS relid, ad.adnum AS attnum
                FROM pg_depend d
                JOIN pg_attrdef ad ON d.classid = 'pg_attrdef'::regclass AND d.objid = ad.oid
                WHERE d.refclassid = 'pg_class'::regclass AND d.refobjid = seq.oid
                UNION
                SELECT d.refobjid, d.refobjsubid
                FROM pg_depend d
                WHERE d.classid = 'pg_class'::regclass AND d.objid = seq.oid
                  AND d.refclassid = 'pg_class'::regclass AND d.refobjsubid > 0
                  AND d.deptype IN ('a', 'i')
            )
            SELECT n.nspname, t.relname, a.attname
            FROM refs r
            JOIN pg_class t ON t.oid = r.relid
            JOIN pg_namespace n ON n.oid = t.relnamespace
            JOIN pg_attribute a ON a.attrelid = r.relid AND a.attnum = r.attnum
            WHERE NOT a.attisdropped
        LOOP
            EXECUTE format('SELECT max(%I)::bigint FROM %I.%I',
                           col.attname, col.nspname, col.relname) INTO column_max;
            used_max := greatest(used_max, column_max);
        END LOOP;
        IF used_max IS NOT NULL AND used_max >= seq.seqstart THEN
            EXECUTE format('SELECT last_value FROM %I.%I', seq.nspname, seq.relname)
                INTO current_value;
            PERFORM pg_catalog.setval(seq.oid::regclass, greatest(used_max, current_value), true);
        END IF;
    END LOOP;
END
$sync$;
```

### 核对每张表行数

```sql
-- 在 Navicat 中分别对 A 库和本地 erp2027 执行；只读查询。
-- 返回 public 中每张表的实际行数，不使用 pg_stat 的估计值。
SELECT jsonb_object_agg(tablename, row_count ORDER BY tablename)::text AS table_counts
FROM (
    SELECT tablename,
           (xpath('/row/n/text()', query_to_xml(
               format('SELECT count(*) AS n FROM %I.%I', schemaname, tablename),
               false, true, ''
           )))[1]::text::bigint AS row_count
    FROM pg_tables
    WHERE schemaname = 'public'
) counts;
```

### 检查序列下一值

```sql
-- 只读：检查普通、共享和 identity 序列的下一值是否超过已存 ID。
WITH sequences AS (
    SELECT c.oid, n.nspname, c.relname, q.seqincrement
    FROM pg_class c
    JOIN pg_namespace n ON n.oid = c.relnamespace
    JOIN pg_sequence q ON q.seqrelid = c.oid
    WHERE n.nspname = 'public'
), refs AS (
    SELECT s.oid AS seqid, ad.adrelid AS relid, ad.adnum AS attnum
    FROM sequences s JOIN pg_depend d
      ON d.refclassid = 'pg_class'::regclass AND d.refobjid = s.oid
    JOIN pg_attrdef ad ON d.classid = 'pg_attrdef'::regclass AND d.objid = ad.oid
    UNION
    SELECT s.oid, d.refobjid, d.refobjsubid
    FROM sequences s JOIN pg_depend d
      ON d.classid = 'pg_class'::regclass AND d.objid = s.oid
    WHERE d.refclassid = 'pg_class'::regclass AND d.refobjsubid > 0
      AND d.deptype IN ('a', 'i')
), maxima AS (
    SELECT r.seqid,
           max((xpath('/row/n/text()', query_to_xml(
               format('SELECT max(%I)::bigint AS n FROM %I.%I', a.attname, n.nspname, t.relname),
               false, true, ''
           )))[1]::text::bigint) AS used_max
    FROM refs r
    JOIN pg_class t ON t.oid = r.relid
    JOIN pg_namespace n ON n.oid = t.relnamespace
    JOIN pg_attribute a ON a.attrelid = r.relid AND a.attnum = r.attnum
    WHERE NOT a.attisdropped
    GROUP BY r.seqid
), states AS (
    SELECT s.*, m.used_max, query_to_xml(
        format('SELECT last_value, is_called FROM %I.%I', s.nspname, s.relname),
        false, true, ''
    ) AS state
    FROM sequences s LEFT JOIN maxima m ON m.seqid = s.oid
), next_values AS (
    SELECT relname, used_max, seqincrement,
           (xpath('/row/last_value/text()', state))[1]::text::bigint
             + CASE WHEN (xpath('/row/is_called/text()', state))[1]::text::boolean
                    THEN seqincrement ELSE 0 END AS next_value
    FROM states
)
SELECT relname, used_max, next_value,
       seqincrement > 0 AND (used_max IS NULL OR next_value > used_max) AS safe
FROM next_values ORDER BY relname;
```
